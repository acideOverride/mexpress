# mExpress Template Structure Guide

## Overview

This document outlines the common structure and requirements for mExpress templates. All templates follow a standardized XML format and include specific sections for functionality, validation, and documentation.

## Template Chain

Templates are interconnected in the following sequence:

Core Development Flow:

1. ask (ask_template.md) - Business-focused solution exploration
2. architect (architect_template.md) - Architecture and technical strategy
3. gpm (gpm_template.md) - Project management and milestone tracking
4. taskmanager (taskmanager_template.md) - Task breakdown and management
5. code (code_template.md) - Code implementation
6. debugger (debugger_template.md) - Issue resolution
7. GIT (git_template.md) - Version control management

Parallel Design Process:

- uxui (uxui_template.md) - Design system and user experience
  - Integrates with ask for user needs and business goals
  - Works alongside architect for technical feasibility
  - Influences implementation in code
  - Maintains consistency through gpm and taskmanager

## Common Template Structure

### 1. XML Declaration

```xml
<?xml version="1.0" encoding="UTF-8"?>
<template_name>
```

### 2. Metadata Section

```xml
<metadata>
    <version>Version number</version>
    <phase>Template phase</phase>
    <purpose>Template purpose</purpose>
    <template_chain>
        <previous>Previous template</previous>
        <current>Current template</current>
        <next>Next template</next>
    </template_chain>
</metadata>
```

### 3. Roo Integration

```xml
<roo_integration>
    <tool_mapping>
        <!-- Tool definitions and permissions -->
    </tool_mapping>
    <environment_context>
        <!-- Working directory and file system context -->
    </environment_context>
    <permission_management>
        <!-- Operation permissions and restrictions -->
    </permission_management>
</roo_integration>
```

### 4. State Management

```xml
<state_management>
    <states>
        <!-- State definitions -->
    </states>
    <transitions>
        <!-- State transition rules -->
    </transitions>
    <validation>
        <!-- State validation requirements -->
    </validation>
</state_management>
```

### 5. Protocol Chains

```xml
<protocol_chains>
    <workflow>
        <!-- Workflow steps and validations -->
    </workflow>
    <validation_chains>
        <!-- Validation procedures -->
    </validation_chains>
    <feedback_chains>
        <!-- Feedback collection and processing -->
    </feedback_chains>
</protocol_chains>
```

### 6. Validation Systems

```xml
<validation_systems>
    <frameworks>
        <!-- Validation frameworks -->
    </frameworks>
    <automation>
        <!-- Automated validation processes -->
    </automation>
</validation_systems>
```

### 7. Documentation Responsibilities

```xml
<documentation_responsibilities>
    <required_documents>
        <!-- Required documentation -->
    </required_documents>
    <maintenance_requirements>
        <!-- Documentation maintenance -->
    </maintenance_requirements>
    <validation_requirements>
        <!-- Documentation validation -->
    </validation_requirements>
</documentation_responsibilities>
```

### 8. Error Recovery

```xml
<error_recovery>
    <detection>
        <!-- Error detection mechanisms -->
    </detection>
    <recovery_procedures>
        <!-- Recovery steps and procedures -->
    </recovery_procedures>
</error_recovery>
```
