# Quality Control Criteria

## 1. QC/ARCH to GPM
This checkpoint validates architectural decisions before project planning.

### Acceptance Criteria:
```markdown
1. Technical Completeness:
   - All system components defined
   - Integration points specified
   - Security measures outlined
   - Performance requirements detailed

2. Resource Feasibility:
   - Technology stack validated
   - Required skills identified
   - Infrastructure requirements clear
   - External dependencies listed

3. Documentation Quality:
   - Architecture diagrams complete
   - Technical specifications detailed
   - Decision rationale documented
   - Risk assessment included
```

### Rejection Criteria:
```markdown
1. Technical Gaps:
   - Missing component specifications
   - Unclear integration points
   - Incomplete security measures
   - Undefined performance metrics

2. Resource Issues:
   - Unavailable required technologies
   - Missing critical skills
   - Unclear infrastructure needs
   - Unresolved dependencies

3. Documentation Issues:
   - Incomplete architecture diagrams
   - Missing technical specifications
   - Undocumented decisions
   - Insufficient risk assessment

Rejection Protocol:
1. Document specific gaps
2. Return to ARCHITECT
3. Request revisions
4. Schedule re-review
```

## 2. QC/GPM to TM
This checkpoint validates project planning before task breakdown.

### Acceptance Criteria:
```markdown
1. Project Planning:
   - Clear milestone definitions
   - Realistic timelines
   - Resource availability confirmed
   - Dependencies mapped

2. Resource Allocation:
   - Team capacity aligned
   - Skill requirements matched
   - Tools and environments ready
   - Budget allocation clear

3. Risk Management:
   - Risks identified and assessed
   - Mitigation strategies defined
   - Contingency plans in place
   - Monitoring points established
```

### Rejection Criteria:
```markdown
1. Planning Issues:
   - Unclear milestones
   - Unrealistic timelines
   - Resource conflicts
   - Unmapped dependencies

2. Resource Problems:
   - Team capacity misalignment
   - Skill gaps
   - Missing tools/environments
   - Budget inconsistencies

3. Risk Concerns:
   - Unaddressed major risks
   - Missing mitigation strategies
   - Inadequate contingencies
   - Unclear monitoring

Rejection Protocol:
1. Identify planning gaps
2. Return to GPM
3. Request adjustments
4. Set review timeline
```

## 3. QC/TM to CODE
This checkpoint validates task specifications before implementation.

### Acceptance Criteria:
```markdown
1. Task Definition:
   - Clear requirements
   - Defined acceptance criteria
   - Test requirements specified
   - Documentation needs outlined

2. Technical Preparation:
   - Development environment ready
   - Access permissions granted
   - Required tools available
   - Dependencies resolved

3. Quality Requirements:
   - Test coverage targets set
   - Performance criteria defined
   - Security requirements clear
   - Code standards specified
```

### Rejection Criteria:
```markdown
1. Task Issues:
   - Unclear requirements
   - Missing acceptance criteria
   - Undefined test requirements
   - Documentation gaps

2. Technical Blockers:
   - Environment issues
   - Access problems
   - Missing tools
   - Unresolved dependencies

3. Quality Gaps:
   - Unclear test requirements
   - Missing performance criteria
   - Undefined security needs
   - Unclear coding standards

Rejection Protocol:
1. Document task issues
2. Return to TASKMANAGER
3. Request clarification
4. Set review deadline
```

## Implementation Guidelines

1. For Each QC Point:
   - Use standardized checklists
   - Document all findings
   - Provide specific feedback
   - Track rejection reasons

2. Rejection Process:
   - Clear documentation of issues
   - Specific improvement requirements
   - Set timeline for fixes
   - Schedule re-review

3. Tracking:
   - Record all rejections
   - Track common issues
   - Monitor resolution time
   - Identify process improvements

4. Communication:
   - Clear rejection notifications
   - Specific feedback to teams
   - Regular status updates
   - Resolution tracking

This ensures:
1. Consistent quality standards
2. Clear rejection criteria
3. Documented improvement needs
4. Trackable quality metrics
